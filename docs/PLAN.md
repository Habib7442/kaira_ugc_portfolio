# Behind the Post — build plan

## Structure

```
raw/                     source media (never edited by scripts)
  creator/*.png|jpg      photos; files with "cutout" in the name are treated as cut-outs
  video(s)/*.mp4|mov     vertical videos
  cases/*.png|jpg        case-study product shots
src/content/
  creator.json           ALL creator content (the only file you edit per creator)
  creator.schema.json    JSON schema for creator.json
  test-creator.json      second creator used to prove the template is reusable
  media.json             GENERATED by `npm run assets` (sizes, srcsets, video variants)
src/render/              pure functions: content -> HTML strings (run at build time)
src/sections/            browser behaviour per section (GSAP, video, player…)
src/lib/                 env flags, motion setup (GSAP/Lenis), capture mode, helpers
src/styles/              design tokens, base, one CSS file per section
public/fonts/            self-hosted woff2 (latin subsets)
public/media/            GENERATED media (committed, so Netlify needs no ffmpeg)
scripts/                 assets.mjs, check-content.mjs, size-report.mjs, media-kit.mjs
```

## Data flow

1. `npm run assets` scans `raw/`, writes optimised files to `public/media/` and a manifest to
   `src/content/media.json`, keyed by the raw path (e.g. `creator/polaroid.png`).
2. `creator.json` refers to media by raw path. `npm run check-content` validates it against the
   schema and checks that every referenced file exists in the manifest.
3. At build time a Vite plugin reads `creator.json` + `media.json` and **pre-renders the whole page
   into `index.html`** (fast first paint, SEO, works before JS). Theme colours become CSS variables.
4. The same data is exposed to the browser as `virtual:content`; `src/main.ts` only adds behaviour.
5. `CREATOR=path/to/other.json` swaps the creator (used by `npm run dev:test` / `build:test`).

## Sections (one render fn + one behaviour module each)

| # | id | Pinned (sticky wrapper) | Notes |
|---|----|----|----|
| 0 | intro | – | CSS-only, ≤1.2s, skipped for returning visitors / capture / reduced motion |
| 1 | cover | 160vh desktop / 120vh mobile | letters in own 3D layer *behind* the cut-out layer, so they can never cover her face |
| 2 | about | – | polaroid tilt + develop, sticker chips, counters |
| 3 | tunnel | 300vh / 220vh | phones transformed individually per frame; nearest 3 play preview loops |
| 4 | orbit | 180vh | ring projected in JS (rotateX 70° ellipse); front half z-index above cut-out, back half below |
| 5 | cases | – | fan-out scrub (desktop) / snap carousel (mobile), GSAP 3D flips |
| 6 | make | – | SVG textPath badge, speed follows scroll velocity |
| 7 | process | desktop: height = track width | mobile: native scroll-snap |
| 8 | contact | – | mailto / ig.me / wa.me, enquiry form → mailto + copy fallback |
| 9 | footer | – | demo disclaimer when `demo: true` |

"Pinned" sections use **CSS `position: sticky` inside a tall wrapper** plus a scrubbed
ScrollTrigger, not GSAP pinning: no pin-spacer reflows and the page can never be scroll-trapped
inside the Instagram in-app browser.

## Modes (classes set on `<html>` by an inline head script before first paint)

- `is-rm` — prefers-reduced-motion: no sticky wrappers, tunnel = grid, orbit = pill wrap, cards = list, badge static.
- `is-lite` — low-power device / Save-Data: tunnel = grid with posters only.
- `is-touch` — no Lenis, no mouse parallax.
- `is-capture` — `?capture=1`, see docs/CAPTURE.md.
- `no-intro` — returning visitor.

## Build order

1. Scaffold, fonts, tokens, PLAN.md
2. Asset pipeline + manifest + size report
3. creator.json, schema, validator, test creator
4. Pre-render plugin + nav + cover (+ intro)
5. About → Tunnel + Player → Orbit → Cases → Make → Process → Contact → Footer
6. Reduced motion / lite / capture mode
7. QA at 390×844, 1440, 1920; test creator; Lighthouse; docs
